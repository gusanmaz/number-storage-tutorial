Chapter 2

The hidden order of counting

The way to read switch patterns as numbers is hidden in an idea we all learned in primary school: place value. Once you truly understand it, binary and hexadecimal become mere dialects.

Reading: ~30 minBefore: Chapter 1

§ 2.1Try adding Roman numerals

Add MCMLXXXIV and XLVII. Hard, isn’t it? In Roman numerals every symbol has a fixed value (M = 1000, C = 100, X = 10…) and a number is read by adding (sometimes subtracting) those values. To add, you first have to translate into some other system in your head.

The system we use today has a different secret: a digit’s value depends on where it stands. Of the two “2”s in 2024, one means two thousand and the other twenty. This idea, and the zero that makes it work, developed in India. In the 9th century the mathematician al-Khwarizmi, working in Baghdad, wrote a book about the system; the Latin title of its translation (“Algoritmi…”) gave us the word algorithm. The system spread through Europe after Fibonacci’s book of 1202.

The best way to really understand place value is to play with it as a machine.

§ 2.2Exploding dots

Below is a machine made of boxes. The rules are simple: you add dots to the rightmost box; when dots pile up in a box they explode, those dots vanish and a single dot appears in the box to the left. Start with base ten, then drop the base to 2 and play the same game.

The machine shows why place value works. A single dot in a box was created by base dots exploding in the box to its right. So every box is worth base times the box to its right. In decimal the boxes are worth 1, 10, 100, 1000; in binary 1, 2, 4, 8, 16…

value = … + d3·b³ + d2·b² + d1·b¹ + d0·b⁰

Here b is the base and the ds are the digits in the boxes. A box can hold at most b − 1 dots (one more explodes), which is why the digits of base b run from 0 to b − 1. Binary having only 0 and 1 fits the switches of Chapter 1 perfectly: a switch is a box that holds at most one dot.

What do the boxes look like if you add 5 dots to the base-2 machine?

Think first, then open

Right to left: 1, 0, 1. So 1012 = 4 + 0 + 1 = 5. You can check it on the machine.

§ 2.3Counting in binary

Counting in binary means flipping the rightmost switch at every step and passing the “carry” to the left when needed. The counter below counts from 0 to 15. Under it, a diagram draws each lamp’s state over time.

Once you notice the pattern in the diagram you never need to memorize binary numbers: the rightmost bit goes 0101…, the next 0011…, the next 00001111… Each column is a version of the previous one running twice as slowly.

§ 2.4Reading a binary number

From right to left the boxes double: 1, 2, 4, 8, 16, 32, 64, 128… To read a binary number you just add up the values of the lamps that are on. Lamps that are off add nothing.

1 1 0 1 0 1 1 0 → 128 + 64 + 16 + 4 + 2 = 214

The other direction, turning a decimal number into binary, is like a balance puzzle. You have one weight each of 128, 64, 32, 16, 8, 4, 2 and 1 grams. One pan holds something that weighs the target number; balance it with weights on the other pan. Target: .

The fastest strategy is to be greedy: start with the biggest weight; keep it on the pan if it does not overshoot the target, take it off if it does; then move to the next smaller one. Because every weight is one more than the sum of all smaller ones (128 = 64 + 32 + … + 1 + 1), this strategy always finds the answer, and every number has exactly one binary spelling.

§ 2.5Converting by division

The balance method is great for small numbers but requires knowing the list of weights. There is a general method that works in any base, and it too comes straight from exploding dots. When you divide the number by the base, the remainder is the dots left unexploded in the rightmost box, and the quotient is the number of dots passed to the left. Repeat until the quotient is zero.

§ 2.6Every base is the same game

Bases 10 and 2 are not special; the machine works in any base. Play with this sentence: is written in base .

Some bases have a special place. Base 8 (octal) and base 16 (hexadecimal) are powers of two: 8 = 2³, 16 = 2⁴. That means you can switch between them and binary without any arithmetic. Let’s see how.

In everyday lifeIn the Linux command chmod 755 every digit is a 3-bit permission group: read (4) + write (2) + execute (1). 7 = 111 = everything, 5 = 101 = read and execute.

§ 2.7Shorthand for long bits: hexadecimal

Think of a 32-bit value: 11011110101011011011111011101111. A pain to read and to write; missing a bit is far too easy. Converting to decimal (3735928559) makes it shorter but loses the link to the bits: we can no longer see which bits are on.

The solution is surprisingly simple: group the bits in fours from the right. 4 bits have 2⁴ = 16 patterns and we give each pattern a single symbol. The digits 0–9 are not enough, so we add the letters A, B, C, D, E, F. Tap the lamps below and change the group size.

So 32 bits shrink to eight hex digits: DEADBEEF. Every digit corresponds to exactly 4 bits, so you can still see which bits are on. Two hex digits = 8 bits; in the next chapter we will call that group of eight a byte.

Programmers write hex numbers with the 0x prefix (0xFF), color codes use # (#FF8800), and texts sometimes use a subscript: FF16. The prefix matters: 0x10 is not ten but sixteen.

Where will you meet hexadecimal?

  • Colors: #FF5733 is three bytes: red, green, blue (Chapter 7).
  • Memory addresses: 0x7FFE42A0 (Chapter 8).
  • Character numbers: U+00E7 = ç (Chapter 6).
  • Network card IDs: a MAC address 00:1A:2B:3C:4D:5E, six bytes.
  • Error codes: on Windows 0x80070005 = “Access denied”.

§ 2.8Bases in code

In Python and JavaScript you can write numbers directly in different bases. They all produce the same number; the base is only a way of writing it.

a = 0b1010        # binary  → 10
b = 0o12          # octal   → 10
c = 0xA           # hex     → 10
print(a == b == c == 10)       # True

bin(255), oct(255), hex(255)   # ('0b11111111', '0o377', '0xff')
f"{255:08b}"                   # '11111111'  pad to 8 digits
int("11111111", 2)             # 255  text to number
int("ff", 16)                  # 255

const a = 0b1010;      // binary → 10
const b = 0o12;        // octal  → 10
const c = 0xA;         // hex    → 10
console.log(a === b && b === c);   // true

(255).toString(2);                 // "11111111"
(255).toString(16);                // "ff"
(5).toString(2).padStart(8, "0");  // "00000101"
parseInt("11111111", 2);           // 255
parseInt("ff", 16);                // 255

§ 2.9Try it yourself

Which is not a valid number in base 7?

  • 660
  • 1234
  • 1780
  • 0
Base 7 digits are 0–6; 7 and 8 are invalid.

What is 1002?

  • 100
  • 4
  • 2
  • 8
1·4 + 0·2 + 0·1 = 4. Appending a 0 to a binary number doubles it.

How is 1111 0011 written in hex?

  • F3
  • E3
  • F11
  • FC
1111 = F, 0011 = 3.

Why do we read the remainders of repeated division from bottom to top?

  • Tradition
  • The last remainder is always 1
  • The quotient grows at every step
  • The first remainder gives the rightmost digit
The first remainder is the dots left unexploded in the rightmost box: the ones digit.

Which number comes after FF in hex?

  • FG
  • G0
  • 100
  • FF1
Both boxes hold the largest digit; +1 causes a chain of explosions: 10016 = 256.
