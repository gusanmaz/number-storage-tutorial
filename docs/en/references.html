Variables & References

In C, a variable is a box at a fixed address. In Python and JavaScript, a variable is a name tag tied to an object somewhere in memory. This difference is behind some of the most common beginner bugs.

⏱ ~30 minPrerequisite: Memory
By the end of this chapter you will
  • be able to explain that in Python/JS an assignment (b = a) copies the reference, not the data;
  • tell mutable and immutable types apart;
  • understand why passing a list to a function can change the original;
  • know the difference between == and is / ===, and between shallow and deep copies.

Box or name tag?

C: variable = box

int a = 10; int b = a; → two separate boxes, each containing 10. Changing b doesn’t affect a. As you saw in the previous chapter, every variable has a fixed address.

Python / JS: variable = name tag

Values (objects) live somewhere in memory. A variable is just a name bound to that object; it holds the object’s address (reference). b = a → no new object; just a second tag on the same object.

This isn’t always a problem. Trouble starts when the object can be changed in place. Step through each scenario in the visualizer below. At some steps you’ll be asked to predict the result before seeing it.

Mutable and immutable types

Immutable

Python: int, float, bool, str, tuple, None
JS: number, string, boolean, null, undefined, bigint

Once created, the object never changes. a = a + 1 creates a new object and moves the a tag there. That makes sharing safe.

Mutable

Python: list, dict, set, your own classes
JS: Array, Object, Map, Set

Operations like append, push and x[0] = … change the object in place. Every name bound to it sees the change.

Common mistake: thinking you made a copy

backup = items does not make a backup! Both names point to the same list. For a real copy use items.copy(), list(items) or items[:] in Python; [...arr] or structuredClone(obj) in JavaScript.

== vs is (and ===)

Equality (==) asks whether two objects have the same contents. Identity (is in Python) asks whether two names point to the same object, i.e. have the same address.

a = [1, 2]
b = [1, 2]
c = a
print(a == b)      # True   same contents
print(a is b)      # False  different objects
print(a is c)      # True   same object
print(id(a), id(c))  # same number: the object's identity (its memory address in CPython)

if x is None:      # always check for None with "is"
    ...

const a = [1, 2];
const b = [1, 2];
const c = a;
console.log(a === b);   // false  for objects, === compares identity!
console.log(a === c);   // true
console.log(5 === 5);   // true   primitives compare by value

// To compare contents (simple cases):
JSON.stringify(a) === JSON.stringify(b);   // true
Don’t compare numbers with is

CPython pre-creates and shares small integers from −5 to 256. So a = 100; b = 100; a is b is usually True, but for larger numbers the result depends on how the code is run. It’s an implementation detail: always compare values with ==.

const doesn’t mean unchangeable

In JavaScript, const means the name cannot be bound to another object; the object itself can still change.

const basket = ["apple"];
basket.push("pear");     // ✓ works: same array, changed in place
basket = ["banana"];     // ✗ TypeError: the name cannot be rebound
Object.freeze(basket);   // to make it truly unchangeable (shallowly)

Summary

  • In Python/JS variables are names bound to objects; assignment copies the reference, not the object.
  • When an immutable object (number, string) “changes”, a new object is actually created.
  • Mutable objects (lists, dicts, arrays, objects) change in place; every name pointing to them sees the change.
  • A list passed to a function is not copied; the function can modify it.
  • == compares contents, is / === on objects compares identity. A shallow copy still shares nested objects.

What does x = [1, 2]; y = x; y.append(3); print(x) print?

  • [1, 2]
  • [1, 2, 3]
  • [3]
  • An error
x and y point to the same list; append changes it in place.

What does s = "cat"; t = s; s = s + "s"; print(t) print?

  • cat
  • cats
  • s
  • An error
Strings are immutable. s + "s" creates a new object; t keeps pointing to the old one.

In JavaScript, what is [1] === [1]?

  • true
  • An error
  • false
  • undefined
Two separate array objects were created; === on objects checks identity.

After a = [[0], [0]]; b = a.copy(); b[0].append(1), what is a?

  • [[0], [0]]
  • [[0, 1], [0, 1]]
  • [[0], [0], 1]
  • [[0, 1], [0]]
copy() is shallow: the outer list is new, but the inner lists are shared.

What’s the best way for a function to return a new list without modifying the one it was given?

  • Assign a new value to the parameter
  • Work on a copy of the list and return it
  • Use global
  • Use is
For example new = lst.copy(); new.append(x); return new. The caller’s list stays intact.
