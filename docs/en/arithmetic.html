Chapter 4

Binary arithmetic

You learned decimal addition in primary school. Binary addition is the same game with a much shorter table. In this chapter we follow, bit by bit, how a processor does the four operations: carries, borrows, overflow, shifts.

Reading: ~35 minBefore: Chapters 1–3

§ 4.1A four-line addition table

To add in decimal we memorized a hundred-line table from 0+0 to 9+9. In binary the table has only four lines:

a + bResultSum bitCarry
0 + 0000
0 + 1110
1 + 0110
1 + 1102 = 201

The last line is exactly the exploding dots of Chapter 2: two dots in a box explode and a carry goes to the left. Look closely at this table and two familiar logic gates appear: the sum bit is 1 when the inputs differ, which is XOR; the carry is 1 when both inputs are 1, which is AND. A circuit made of these two gates is called a half adder.

In multi-digit addition each column must also take the carry coming from the right into account, so it adds three bits. That three-input circuit is called a full adder. Tap the inputs below:

§ 4.2Adding with carries

Adding two multi-bit numbers is the same as column addition in primary school: start at the rightmost column, add three bits (a, b, carry) in each column, write the sum bit below and move the carry one place left. Change the numbers and step column by column: + .

This design is called a ripple-carry adder, because the carry ripples from one column to the next like a wave. In a 64-bit addition the leftmost column has to wait for the carry to travel through 63 columns. Real processors use more elaborate circuits that compute the carries in advance (carry-lookahead); the result is the same, just faster.

§ 4.3Unsigned overflow and the carry flag

An unsigned integer is the simplest reading, where every bit carries a positive place value: with n bits, 0 to 2n − 1. The sum of two n-bit unsigned numbers can need n + 1 bits. The extra bit does not fit in the box and is dropped; what remains is:

result = (a + b) mod 2n

But the processor does not forget that extra bit entirely. It keeps it in a special bit called the carry flag (C). Right after an addition, a program can check C to find out whether it overflowed. The flag’s real talent is something else: adding big numbers piece by piece. An 8-bit processor adds two 16-bit numbers by first adding the low bytes, then the high bytes plus C. Thanks to this “add with carry” (ADC) instruction an 8-bit machine can work with numbers as large as it likes.

§ 4.4Subtracting with borrows

The column rules for subtraction are: 1 − 0 = 1, 1 − 1 = 0, 0 − 0 = 0, and the troublesome 0 − 1. In decimal we would borrow ten from the neighbor; in binary the one borrowed from the neighbor is worth two in this column. 0 − 1 becomes 1 and a borrow of 1 is owed to the next column. Follow − ; try making the second number bigger than the first too.

Going below the lower limit (0) by subtracting a bigger number from a smaller one is often called underflow in everyday speech; the result is still taken mod 2n: 3 − 5 = 256 − 2 = 254. We will meet “real” floating-point underflow in Chapter 6.

The second tab previews the big idea of the next chapter: a − b = a + (flipped b) + 1. The processor needs no separate subtraction circuit; it is enough to put NOT gates in front of one adder input and set the first carry to 1. In Chapter 5 we will see why this is true and how negative numbers grow out of this idea.

A chain of borrows forms across every column and the result is 11111111 = 255, with a borrow leaving on the left. In the unsigned world, going back from 0 wraps to the largest number, just as going back one hour from 0 on a clock lands on 11. In the next chapter we will read that same pattern as −1.

§ 4.5Shifting: multiplying and dividing by 2

Appending a 0 to a decimal number multiplies it by 10. Shifting all bits of a binary number one place left (appending a 0 on the right) multiplies it by 2; shifting one place right (dropping the rightmost bit) divides it by 2 and rounds down. These are among the cheapest things a processor can do.

Compilers use this trick all the time. Instead of x * 8 they write x << 3, and instead of x * 10 they write (x << 3) + (x << 1), because 10 = 8 + 2. Likewise the remainder modulo a power of 2 is a mask: x % 8 = x & 7, because the remainder of dividing by 8 is exactly the last 3 bits.

§ 4.6Multiplication: shift and add

Binary multiplication is the easiest form of long multiplication, because every digit of the multiplier is 0 or 1. If it is 1 you write the multiplicand shifted to that digit’s position; if it is 0 you write nothing. Then you add the partial products. No times table, just shifting and adding. × :

§ 4.7Division: shift and subtract

Division is long division in binary, and again every step has only two options: does the divisor fit into the current remainder? If it does, subtract and write 1 in the quotient; if not, write 0. Then bring down the next bit. ÷ :

With negative numbers languages disagree: C and Java round toward zero (−7 / 2 = −3), Python rounds down (−7 // 2 = −4). The sign of the remainder changes accordingly. § 4.8Unsigned integers in code

C and C++ have explicit unsigned types and their overflow is well defined: the result is always taken modulo 2n. Python has no unsigned type and its integers grow without limit; to imitate an unsigned box you mask the result. In JavaScript, typed arrays are those boxes themselves. There is also saturating arithmetic: stopping at the limit instead of wrapping. When brightening a pixel in image processing, 250 + 10 becoming 4 would be a disaster; it should stop at 255.

#include <stdint.h>
uint8_t a = 200, b = 100;
uint8_t s = a + b;      // 44   (300 mod 256)
uint8_t d = 3 - 5;      // 254  (wraparound)
uint32_t big = 4000000000u;   // unsigned 32-bit: up to 4 billion
unsigned x = 13;
x << 1;   // 26     x >> 1;   // 6     x & 7;   // 5 (x % 8)

a, b = 200, 100
print((a + b) & 0xFF)        # 44   imitate an 8-bit box
print((3 - 5) % 256)         # 254
print(13 << 1, 13 >> 1)       # 26 6
print(13 * 10 == (13 << 3) + (13 << 1))   # True
q, r = divmod(200, 7)        # (28, 4)
print(min(250 + 10, 255))    # 255  saturating addition

const u = new Uint8Array([200]);
u[0] += 100;                 // 44   wraps around
const c = new Uint8ClampedArray([250]);
c[0] += 10;                  // 255  saturates (canvas pixels work like this)
console.log((3 - 5) >>> 0);  // 4294967294  unsigned 32-bit
console.log(Math.floor(200 / 7), 200 % 7);   // 28 4

The whole secret of binary arithmetic: addition column by column with carries, subtraction with borrows (or “flip, add 1, add”), multiplication is shift and add, division is shift and subtract. In a fixed-width box the result is always modulo 2n; the bit that overflows stays in the C flag.

§ 4.9Try it yourself

1011 + 0110 = ?

  • 1101
  • 1111
  • 10001
  • 1001
11 + 6 = 17 = 100012. In a 4-bit box the result would be 0001 with C = 1.

Which operation is the “sum” output of a full adder?

  • a ⊕ b ⊕ c (XOR)
  • a · b · c (AND)
  • a + b + c (OR)
  • NOT a
The sum bit is 1 when an odd number of inputs are 1: a three-input XOR.

8-bit unsigned: what is 250 + 10, and the C flag?

  • 260, C = 0
  • 255, C = 1
  • 4, C = 0
  • 4, C = 1
260 − 256 = 4; the ninth bit goes into the C flag.

What is x << 4 equal to?

  • x + 4
  • x × 16
  • x × 4
  • x ÷ 16
Every left shift is ×2: 24 = 16 (as long as nothing overflows).

What can replace x % 16 (for x ≥ 0)?

  • x >> 4
  • x | 15
  • x & 15
  • x ^ 16
The remainder mod 16 is the last 4 bits; the mask 15 = 11112 selects them.
