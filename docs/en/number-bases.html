Number Bases

Every number system is built on the same idea: a limited set of digits and value that depends on position. Once you get this, binary, octal and hex are just details.

⏱ ~25 minPrerequisites: none
By the end of this chapter you will
  • be able to explain what a “base” is and which digits a base uses;
  • see why counting in any base moves forward by “carrying”;
  • convert a number from any base to decimal using place values;
  • convert a decimal number to any base using repeated division.

What is a base (radix)?

The base of a number system is how many different digits it uses. The system we use every day has ten digits (0, 1, 2, …, 9), so its base is 10.

The basic rule

A base-b system uses the digits 0 through b − 1. There is no digit for b itself!

base 2 → 0 1  ·  base 8 → 0 … 7  ·  base 10 → 0 … 9  ·  base 16 → 0 … 9, A … F

Bases above 10 need new digit symbols. Hex uses letters: A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

Think first

Which digits does base 5 use? Does the digit 5 exist there?

Show answer

0, 1, 2, 3 and 4. There is no digit five; the number “five” is written 105 in base 5 (one five, zero ones).

Counting is really carrying

Think of an old car odometer: the rightmost wheel goes back to 0 after 9 and pushes the wheel on its left forward by one. This is a carry. Counting works the same way in every base; the only difference is when a wheel wraps around. In base 2 a wheel only flips between 0 and 1, so carries happen all the time.

Common mistake: “10” is not always ten

102 = two, 108 = eight, 1016 = sixteen. In any base, 10 means “one base, zero ones” — the base itself.

Place value (positional notation)

A digit’s value depends on where it sits. Of the two 2s in 2024, one means “two thousand” and the other means “twenty”. Each position is a power of the base:

value = dk×bk + … + d2×b2 + d1×b1 + d0×b0 d = digit, b = base. The rightmost position is 0 and positions increase to the left. Remember: b⁰ = 1.

The same formula works in every base. Just replace 10 with your base.

Place value explorer

Type a number and choose its base. See which power each digit is multiplied by and what it adds to the total. Zero digits are faded because they add nothing.

From any base to decimal

The method is exactly the formula above: multiply each digit by its place value and add. Two examples:

10112 → decimal

  1    0    1    1
 2³   2²   2¹   2⁰
  8    4    2    1

1×8 + 0×4 + 1×2 + 1×1
= 8 + 2 + 1 = 11

2F16 → decimal

  2     F
16¹   16⁰
 16     1

2×16 + 15×1     (F = 15)
= 32 + 15 = 47

From decimal to any base: repeated division

To go the other way, we divide by the target base again and again and write down each remainder. We stop when the quotient reaches 0. Reading the remainders from last to first gives the result.

Why does it work? Try it in decimal first

Divide 2024 by 10: remainder 4 (the ones digit), quotient 202. Divide again: remainder 2 (tens), quotient 20. Then remainder 0, quotient 2; then remainder 2, quotient 0. The remainders come out as 4, 2, 0, 2 — the digits from right to left! number % base always gives the rightmost digit, and number // base gives the number with that digit removed. That is why we write the remainders in reverse.

The same algorithm is a few lines of Python. % gives the remainder, // integer division:

def to_base(number, base):
    if number == 0:
        return "0"
    digits = "0123456789ABCDEF"
    result = ""
    while number > 0:
        remainder = number % base           # rightmost digit
        result = digits[remainder] + result # prepend it
        number = number // base             # drop that digit
    return result

print(to_base(25, 2))    # 11001
print(to_base(255, 16))  # FF
print(to_base(100, 8))   # 144

Octal and 3 bits

Octal uses the digits 0–7. It is special because 8 = 2³: each octal digit corresponds to exactly 3 bits. So converting binary ↔ octal needs no arithmetic at all — just group the bits in threes from the right. 

011 010 110    ← 11010110₂ (padded on the left with 0)
 3   2   6     → 326₈
In the real world: Linux file permissions

Each digit in chmod 755 script.sh is a 3-bit permission group: read (4), write (2), execute (1).

Today hex is used far more than octal, because modern computers work in 8, 16, 32 and 64-bit units. These divide evenly by 4 but not by 3: 1 byte = 2 hex digits (neat), but 1 byte = 2.67 octal digits.

Summary

  • Base = number of distinct digits. Base b uses digits 0 … b−1.
  • A digit’s value = digit × bposition; positions start at 0 on the right.
  • Other base → decimal: add up the place values.
  • Decimal → other base: divide repeatedly, write the remainders in reverse.
  • Bases that are powers of 2 have shortcuts: an octal digit = 3 bits, a hex digit = 4 bits.

Which of these is not a valid number in base 7?

  • 660
  • 1234
  • 1780
  • 0
Base 7 uses the digits 0–6. The 7 and 8 in 1780 are invalid.

What is 1002 in decimal?

  • 100
  • 4
  • 2
  • 8
1×2² + 0×2¹ + 0×2⁰ = 4. In binary, each 0 appended to the right doubles the value.

In repeated division, why do we write the remainders in reverse order?

  • It is just a convention
  • Because the quotient grows each step
  • Because the last remainder is always 1
  • Because the first remainder is the rightmost (ones) digit
number % base always yields the rightmost digit. We find the digits right to left, so we reverse them when reading.

Which is true about 1016 and 1610?

  • They are the same number
  • 1016 is bigger
  • 1610 is bigger
  • They cannot be compared
1016 = 1×16 + 0 = 16. Both are sixteen.

What permissions do “others” get with chmod 640?

  • rw-
  • r--
  • --- (none)
  • rwx
The last digit 0 = 000 → no permissions. (6 = 110 = rw-, 4 = 100 = r--)
