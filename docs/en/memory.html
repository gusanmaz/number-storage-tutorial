Chapter 10

Memory: one long strip of bytes

So far we have looked at single numbers, letters and colors. They all live in the same place: one strip made of billions of numbered bytes. In this chapter we walk along that strip.

Reading: ~40 minBefore: Chapters 3, 5 and 7

§ 10.1Every byte has an address

Think of the computer’s main memory (RAM) as a very long street. Every house on the street holds exactly 8 bits, one byte, and every house has a door number: its address. The processor tells memory “give me the byte at this address” or “write this at that address”. It knows nothing else; concepts like variables, arrays and strings are all built on top of these two commands.

Since addresses are written in bits too, how many bytes a processor can reach depends on the number of address bits. With -bit addresses you can reach at most of memory. That is why 32-bit computers could not use more than 4 GB of RAM. Today’s 64-bit processors use 48 bits in practice, which is 256 TiB.

§ 10.2Bytes don’t know what they are

We are back to the main idea of Chapter 1: a bit pattern carries no meaning of its own. Eight bytes side by side in memory can be text, two integers, a floating-point number or an address. The program that reads them decides what we are looking at. Edit the bytes below (in hex) and look at different readings of the same 8 bytes.

§ 10.3Byte order: endianness

Numbers bigger than a byte spread across several addresses. The 32-bit number 0x12345678 takes 4 bytes: 12, 34, 56, 78. Which one goes to the lowest address? There are two answers, and both are in use:

  • Big endian (big end first): the most significant byte at the lowest address. This is how we write numbers, and how network protocols send them (“network byte order”).
  • Little endian (little end first): the least significant byte at the lowest address. Intel/AMD (x86) and nearly all ARM processors work this way, so most devices you use today do.
Where the name comes from“Endian” comes from Jonathan Swift’s Gulliver’s Travels. In the novel two nations go to war over whether a boiled egg should be cracked at the big end (Big-Endians) or the little end (Little-Endians). In 1980 computer scientist Danny Cohen borrowed the terms to say that this debate was just as arbitrary.

Byte order matters when data moves between machines. A file format or network protocol always specifies it: PNG and network packets are big endian, BMP and WAV files little endian.

§ 10.4Variables, arrays, pointers

When you write int age = 17; in a program, the compiler reserves 4 bytes of memory and pairs the name “age” with that address. A variable name is a memorable nickname for an address. An array is elements of the same type laid out one after another in memory; the address of arr[i] is a simple calculation:

address(arr[i]) = start + i × element size

This formula is also why arrays start at zero: the first element is zero away from the start. A pointer is a variable whose value is an address. Run the small C program below step by step and watch memory change.

What would happen if the program wrote arr[5]? The array only has 3 elements.

Think first, then open

C does not check: following the formula it goes to start + 5 × 4 and reads or overwrites whatever is there. Maybe it corrupts another variable, maybe the program crashes. This “buffer overflow” is one of the most exploited security holes in history. Python and JavaScript check the bounds on every access and raise an error.

Pointers live in memory too: on a 64-bit system every pointer is 8 bytes. A pointer that points nowhere is called NULL and its value is usually 0. A program that tries to access address 0 is stopped by the operating system; that is the famous “segmentation fault”.

AlignmentProcessors read a 4-byte number faster from addresses that are multiples of 4. So compilers sometimes put empty bytes (padding) between variables. That is why the gray bytes after the char and after the array are empty in the figure.

§ 10.5Files are byte sequences too

A disk is a byte strip that is much slower than memory but permanent. A file is a sequence of bytes on that strip plus a name. The fact “this is a PNG image” is written inside the file, usually in the first few bytes. These bytes are called a magic number or file signature. Changing the file extension does not change the file type; the signature stays the same.

The PNG signature is especially clever: the first byte is above 127 (to warn programs that mistake the file for text), it contains Windows (0D 0A) and Unix (0A) line endings and 1A (“end of file” in old DOS). If a faulty transfer “fixes” the line endings, the signature breaks and the error is noticed immediately.

Memory and disk alike are just numbered bytes. The address says where, the type says how to read it, and the byte order says how multi-byte values are laid out. Know those three and you can read any data byte by byte.

§ 10.6Try it yourself

On a little endian machine the 32-bit 0xAABBCCDD is written at address 0x100. The byte at 0x100?

  • AA
  • DD
  • BB
  • CC
Little end first: the least significant byte (DD) goes to the lowest address.

If an int (4-byte) array starts at 0x2000, where is arr[3]?

  • 0x2003
  • 0x2012
  • 0x200C
  • 0x2030
0x2000 + 3 × 4 = 0x2000 + 12 = 0x200C.

What does a pointer variable hold?

  • A memory address
  • The variable’s name
  • Always an integer value
  • The array length
A pointer’s value is an address; *p reads the value at that address.

What happens when you rename a file from .png to .txt?

  • The file turns into text
  • The bytes are re-encoded
  • The file is corrupted
  • The bytes stay the same; only the program that opens it changes
The content, including the signature in the first bytes, stays exactly as it was.

How many bytes can 16-bit addresses reach at most?

  • 16
  • 65,536
  • 256
  • 4,294,967,296
216 = 65,536 = 64 KiB. That is where the Commodore 64 got its name.
