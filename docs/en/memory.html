Memory

So far you have seen how numbers, letters, colors and sounds become bytes. In this chapter you will learn where those bytes go: addresses, byte order, arrays and pointers.

Memory: a giant array of numbered boxes

Picture RAM as a very long row of little boxes, each holding exactly one byte. Each box has a number: its address. 8 GB of RAM has about 8.6 billion boxes. The CPU says “fetch the byte at 0x7FFE0010” and gets that box’s contents.

Why are addresses written in hex?

Addresses are numbers too, and their bits matter: which memory block, which page, what alignment… Hex shows this structure because each digit is exactly 4 bits. For example, “round” addresses like 0x1000 and 0x2000 are the starts of 4096-byte pages. In decimal, 4096 and 8192 give no hint of that.

Multi-byte values: byte order (endianness)

An int takes 4 bytes — but in which order are those 4 bytes laid out? There are two conventions. In big-endian (“big end first”) the most significant byte goes to the lowest address; that’s the order humans read. In little-endian it’s the reverse: the least significant byte comes first.

Same number, two orders

In the real world

Intel/AMD (x86) and nearly all ARM processors (phones, Apple M-series) are little-endian. Internet protocols, however, send numbers big-endian (“network byte order”). That’s why network code has converter functions like htonl(). The names come from Gulliver’s Travels, where two peoples go to war over which end of an egg to crack.

Memory simulator

Now declare your own variables and watch how they are placed in memory. The simulator behaves like a real C compiler: each type has a size, and variables are aligned to addresses that are multiples of their size.

Declare a variable, write it to memory

What you see in the simulator
  • Striped gray bytes are padding. An int that follows a char is moved to a multiple of 4, because CPUs read aligned data much faster.
  • A text (char[]) takes 1 byte per ASCII character plus a trailing 00 (null).
  • A pointer’s value is another variable’s address; its bytes show that address written little-endian.
  • Switching byte order only changes the layout of multi-byte values; chars and text stay the same.

Arrays: values side by side

An array is a set of elements of the same type stored one after another in memory. That’s why the address of element i can be found with one multiplication and one addition. It is also why array indices start at 0: the index says how many elements away from the start we are.

address(array[i]) = start address + i × element size

Pointers: variables that hold addresses

Since everything has an address, we can store addresses in variables too. A variable whose value is an address is called a pointer. On 64-bit systems a pointer is 8 bytes. In C, &x means “the address of x” and *p means “the value at the place p points to”.

Pointer dangers

C and C++ let you work with addresses directly, and that power brings risk. Running past the end of an array (buffer overflow), using freed memory (use-after-free) or reading through a NULL pointer can crash a program or open a security hole. Python, JavaScript and Java hide pointers for this reason; in the next chapter you’ll see the references they use instead.

Stack and heap

Stack

Local variables of functions live here. Space is reserved when a function is called and freed automatically when it returns. Very fast but small (usually a few MB).

Heap

Data whose size is only known at run time or that lives a long time (lists, objects) goes here. Managed by hand in C (malloc/free), automatically in Python and JS (garbage collector).

Summary

  • Memory is made of numbered (addressed) boxes of 1 byte each. Addresses are usually written in hex.
  • Multi-byte values are stored little-endian (x86, ARM) or big-endian (network).
  • Each type has a size; variables are aligned and padding may appear between them.
  • Address of an array element = start + i × size. That is why indices start at 0.
  • A pointer is a variable whose value is an address: &x gives the address, *p the value there.

In what order is 0xAABBCCDD stored in memory on a little-endian machine?

  • AA BB CC DD
  • DD CC AA BB
  • BB AA DD CC
  • DD CC BB AA
Little-endian: the least significant byte (DD) at the lowest address.

If int arr[10] (int = 4 bytes) starts at 0x2000, where is arr[5]?

  • 0x2005
  • 0x2014
  • 0x2020
  • 0x2050
0x2000 + 5 × 4 = 0x2000 + 20 = 0x2000 + 0x14 = 0x2014.

On a 64-bit system, how big are char* and double* pointers?

  • Both 8 bytes
  • 1 and 8
  • Both 4 bytes
  • 1 and 4
Whatever a pointer points to, it holds an address; on a 64-bit system an address is 8 bytes.

After int x = 5; int *p = &x; *p = 9; what is x?

  • 5
  • The address of x
  • 9
  • Undefined
*p = 9 writes 9 where p points — that is, into x.

A char (1 B) followed by an int (4 B) are declared; the char is at 0x1000. Where will the int most likely go?

  • 0x1001
  • 0x1004
  • 0x1008
  • 0x1002
ints are aligned to multiples of 4; 0x1001–0x1003 are left as padding.
