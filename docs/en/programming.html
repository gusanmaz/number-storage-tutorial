Number literals

Both languages use the same prefixes. They all produce ordinary numbers of the same type; the base is only the way it is written.

const a = 0b1010;      // binary  → 10
const b = 0o12;        // octal   → 10
const c = 0xA;         // hex     → 10
const d = 10;          // decimal → 10
console.log(a === b && b === c && c === d);   // true

const million = 1_000_000;  // underscores are for readability only
const mask    = 0b1111_0000;

Conversion functions

const n = 255;
// number → string
n.toString(2);                    // "11111111"
n.toString(16);                   // "ff"
n.toString(16).toUpperCase();     // "FF"
n.toString(2).padStart(16, "0");  // "0000000011111111"

// string → number
parseInt("11111111", 2);          // 255
parseInt("ff", 16);               // 255
parseInt("0xFF");                 // 255  (recognises the 0x prefix)
Number("0b1010");                 // 10   (Number recognises all prefixes)

n = 255
# number → string
bin(n)              # '0b11111111'
hex(n)              # '0xff'
oct(n)              # '0o377'
format(n, "b")      # '11111111'  (no prefix)
f"{n:08b}"          # '11111111'  pad to 8 digits
f"{n:04X}"          # '00FF'      uppercase hex, 4 digits
f"{n:#x}"           # '0xff'

# string → number
int("11111111", 2)  # 255
int("ff", 16)       # 255
int("0xff", 0)      # 255  (base 0 = infer from prefix)

Bitwise operators

Bitwise operators process the bits at the same position in two numbers, one by one. The rules:

aba & b (AND)a | b (OR)a ^ b (XOR)
00000
01011
10011
11110

~a (NOT) flips every bit. a << n shifts the bits n places left (× 2ⁿ), a >> n shifts them right (÷ 2ⁿ, rounding down).

Masks: reading and changing a single bit

    

        A mask is a number that is 1 only in the positions we care about. 1 << n gives a mask with only bit n set.
        These four patterns appear everywhere, from games to operating systems:
    

    

        

            
GoalPatternWhy it works

            
                
Is bit n set?(x >> n) & 1Moves the bit to the far right and clears the others

                
Set bit n (make it 1)x | (1 << n)OR-ing in a 1 leaves the other bits alone

                
Clear bit n (make it 0)x & ~(1 << n)The inverted mask: that bit 0, the rest 1

                
Toggle bit nx ^ (1 << n)XOR with 1 flips, XOR with 0 keeps

            
        

    

    

        Masks in the real world
        
    
            
  • Colors: extract the green channel from 0xRRGGBB: (color >> 8) & 0xFF.
    • 
            
  • Permissions: on Linux, mode & 0o200 checks whether the owner can write (rwx = 4, 2, 1).
    • 
            
  • Flags: a game can store states like JUMPING = 1, ON_GROUND = 2, HURT = 4 in one number: state |= HURT.
    • 
            
  • Even/odd: x & 1 is 1 for odd numbers — the bitwise version of x % 2.
    • 
            
  • Networks: IP address & subnet mask = network address.
    • 
        

    


const color = 0xFF8800;
const r = (color >> 16) & 0xFF;   // 255
const g = (color >> 8)  & 0xFF;   // 136
const b =  color        & 0xFF;   // 0
const back = (r << 16) | (g << 8) | b;   // 0xFF8800 again



    
Language-specific pitfalls

    

        

            
JavaScript

            
    
                
  • All numbers are 64-bit doubles. Integers above 2⁵³ can’t be stored exactly: 2**53 + 1 === 2**53 → true. Use BigInt (123n) for big integers.
    • 
                
  • Bitwise operators first convert numbers to 32-bit signed integers: 1 << 31 → -2147483648. Use >>> 0 for an unsigned result.
    • 
                
  • (-5).toString(2) → "-101"; to see two’s complement use (-5 >>> 0).toString(2).
    • 
                
  • parseInt("12px") → 12 but Number("12px") → NaN.
    • 
            

        

        

            
Python

            
    
                
  • Integers are unbounded; they never overflow. But float is still a 64-bit double.
    • 
                
  • bin(-5) → '-0b101'. Python doesn’t show two’s complement; for an 8-bit view use bin(-5 & 0xFF) → '0b11111011'.
    • 
                
  • ~5 → -6 (because ~x = −x − 1).
    • 
                
  • / always gives a float (7 / 2 = 3.5); use // for integer division.
    •

Summary

        
    
            
  • Prefixes: 0b binary, 0o octal, 0x hex. They all produce the same number type.
    • 
            
  • JS: n.toString(base), parseInt(text, base). Python: bin/hex/oct, format/f-strings, int(text, base).
    • 
            
  • & (both 1), | (at least one 1), ^ (different → 1), ~ (flip), << (× 2ⁿ), >> (÷ 2ⁿ).
    • 
            
  • Mask patterns: read (x>>n)&1, set x|(1<<n), clear x&~(1<<n), toggle x^(1<<n).
    • 
        

    


    

        

            
What is 0b1100 & 0b1010?

            
  • 0b1110 (14)
  • 0b1000 (8)
  • 0b0110 (6)
  • 0b0010 (2)

            
Only the bit that is 1 in both numbers (the leftmost) stays 1.

        

        

            
What is 5 << 3?

            
  • 8
  • 15
  • 53
  • 40

            
Shifting left by 3 multiplies by 2³ = 8: 5 × 8 = 40.

        

        

            
What does int("1F", 16) return in Python?

            
  • 31
  • "31"
  • 116
  • An error

            
1 × 16 + 15 = 31 (as a number).

        

        

            
What is x ^ x always equal to?

            
  • x
  • A number with all bits 1
  • 0
  • 2x

            
XOR-ing identical bits always gives 0. (A classic way to zero a register in assembly.)

        

        

            
Why is 0.1 * 3 === 0.3 false in JavaScript?

            
  • There’s a bug in JavaScript
  • Numbers are IEEE 754 doubles, so 0.1 can’t be stored exactly
  • You should use == instead of ===
  • 0.3 is a string

            
Remember the Floating Point chapter: 0.1 * 3 = 0.30000000000000004.
