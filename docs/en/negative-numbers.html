Negative Numbers & Overflow

Memory has no special symbol for a minus sign — only bits. So how is −5 stored? The answer is a clever trick used by almost every computer: two’s complement.

⏱ ~30 minPrerequisites: Binary, Bits & Bytes
By the end of this chapter you will
  • be able to explain why a simple “sign bit” is not good enough;
  • convert numbers to and from 8-bit two’s complement;
  • calculate the ranges of signed and unsigned integers;
  • understand what overflow is and why it is dangerous.

First idea: reserve a bit for the sign

The obvious solution is to use the leftmost bit as the sign: 0 = plus, 1 = minus, and the remaining 7 bits as the magnitude. This is called sign–magnitude. +5 = 00000101, −5 = 10000101. Simple, but it has two big problems:

1. Two zeros

00000000 = +0
10000000 = −0

Two different bit patterns for the same value. Every comparison must check both, and one value is wasted.

2. Addition breaks

  00000011 (+3)
+ 10000011 (−3)
= 10000110 (−6 ?!)

Ordinary binary addition gives the wrong answer. The CPU would need a separate subtraction circuit.

The fix: two’s complement

The idea is surprisingly simple: give the leftmost bit a weight of −128 instead of +128. Every other bit stays the same. Now whenever the leftmost bit is 1, the number automatically becomes negative.

Same bits, two readings

Click the bits. Compare the unsigned (leftmost bit +128) and signed (leftmost bit −128) readings of the same 8 bits.

Presets:
Did you notice?
  • If the leftmost bit is 1, the number is negative. That’s why it is still called the “sign bit”.
  • 11111111 = −128 + 127 = −1. All ones is always −1.
  • Zero has only one pattern: 00000000. There is no “−0”.
  • Numbers 0–127 look the same in both readings.

Negating a number: flip, then add 1

For hand calculation there is a handy rule. To find the negative of a number:

  1. Write the number (its positive form) in 8 bits.
  2. Flip every bit (0 → 1, 1 → 0). This is the “one’s complement”.
  3. Add 1.

Flip, add 1 — step by step

It works in both directions: negate −5 (flip + 1) and you are back to +5.

Why it works: the number wheel

Imagine laying out the 4-bit numbers around a clock face. After 1111 comes 0000; the wheel wraps around. One step backwards from 0000 lands on 1111. So calling 1111 “−1” makes perfect sense! Likewise 1110 = −2, 1101 = −3… Two’s complement simply assigns the right half of the wheel to positive numbers and the left half to negative ones.

4-bit number wheel

Move around the wheel with +1 and −1. Switch the reading and see what happens when you cross the red line: that is the overflow point.

On the wheel, adding x means x steps clockwise and subtracting x means x steps anticlockwise. Going 3 steps anticlockwise lands at the same place as going 13 steps clockwise (16 − 3 = 13). That is why the CPU can subtract by adding the negative: 7 − 3 = 7 + (−3). A single adder circuit is enough! 

  0111   (+7)
+ 1101   (−3)
------
 10100   → the 5th bit is dropped → 0100 = +4 ✓

Signed and unsigned ranges

n-bit two’s complement numbers range over −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1. The negative side has one extra number, because zero takes a slot on the positive side.

Overflow

If the result of an operation does not fit in the available bits, overflow happens and the value “wraps around” the wheel. In an 8-bit signed number, 127 + 1 becomes −128! The program doesn’t crash; it silently computes the wrong answer. That makes overflow one of the sneakiest bugs in software. 

// JS numbers are normally 64-bit floats; typed arrays let us see 8-bit overflow
const a = new Int8Array(1);
a[0] = 127;
a[0] += 1;
console.log(a[0]);        // -128  (overflow!)

const u = new Uint8Array([255]);
u[0] += 1;
console.log(u[0]);        // 0

# Python integers grow without limit, they never overflow:
print(2 ** 100)            # 1267650600228229401496703205376

# But if we mimic C types we can see overflow:
import ctypes
print(ctypes.c_int8(127 + 1).value)    # -128
print(ctypes.c_uint8(255 + 1).value)   # 0

#include <stdint.h>
uint8_t  u = 255;  u = u + 1;   // 0    (unsigned wrap-around is well defined)
int8_t   s = 127;  s = s + 1;   // -128 (in practice; the conversion is implementation-defined)
int      x = 2147483647;
x = x + 1;                      // UNDEFINED BEHAVIOUR! signed int overflow

Pac-Man, level 256 (1980)

The level counter was 8 bits. When it overflowed at level 256, half the screen filled with garbage and the game became unplayable.

🚀

Ariane 5 (1996)

A 64-bit floating-point velocity value did not fit when converted to a 16-bit signed integer. The rocket self-destructed 37 seconds after launch.

📺

Gangnam Style (2014)

YouTube’s view counter was a 32-bit signed integer, max 2,147,483,647. As the video approached that limit, YouTube moved the counter to 64 bits.

⏰

The year 2038 problem

Many systems store time as seconds since 1970 in a 32-bit signed integer. On 19 January 2038 at 03:14:07 UTC that number will overflow.

Summary

  • In two’s complement the leftmost bit has a negative weight (−128 in 8 bits). If it is 1, the number is negative.
  • To negate: flip the bits, add 1.
  • There is a single zero, and the adder circuit also handles subtraction.
  • n-bit signed range: −2ⁿ⁻¹ … 2ⁿ⁻¹ − 1 (8 bits: −128 … 127).
  • If a result doesn’t fit, it overflows and silently wraps around.

What is 11111111 in 8-bit two’s complement?

  • 255
  • −1
  • −127
  • −128
−128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = −1.

Which is the 8-bit two’s complement representation of −6?

  • 10000110
  • 11111001
  • 00000110
  • 11111010
6 = 00000110 → flip: 11111001 → +1: 11111010. (10000110 is sign–magnitude.)

In an 8-bit signed variable, what is 127 + 1?

  • −128
  • 128
  • 0
  • The program stops with an error
01111111 + 1 = 10000000 = −128. On the wheel we crossed from positive to negative: overflow.

What is the smallest value of a 16-bit signed integer?

  • −65,536
  • −32,767
  • −32,768
  • 0
−2¹⁵ = −32,768.

What is the main reason CPUs use two’s complement?

  • It fits more positive numbers
  • The same circuit can do both addition and subtraction
  • It is easier to read
  • It uses fewer bits
a − b = a + (−b). Negative numbers give correct results with plain binary addition; no separate subtraction circuit is needed.
