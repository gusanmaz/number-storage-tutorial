Chapter 9

Lesser-known formats

Binary integers, ASCII, Unicode and IEEE 754 are the famous agreements. But computers are full of stranger, cleverer encodings invented to solve one particular problem: codes that correct errors, integers that save space, counting schemes for mechanical sensors, bytes turned into text.

Reading: ~55 minBefore: Chapters 2–7

Designing a data format is always a trade. Plain binary takes the least space but is hard for people to read. Saving space costs speed, being robust against errors costs extra bits. Every format in this chapter picked a different point in that trade, and each one is still running somewhere today, maybe in your pocket right now.

§ 9.1BCD: storing decimal digits one by one

Binary-coded decimal (BCD) does not store a number as a whole but stores each decimal digit separately in 4 bits. 59 is 111011 in binary; in BCD 5 = 0101 and 9 = 1001 are written side by side: 0101 1001. It looks like hex but is not: only 10 of the 16 four-bit patterns are used, the A–F patterns are forbidden.

Why accept the wasted space? Because talking to the decimal world gets easy. Calculators, digital clocks and the real-time clock (RTC) chips in computers store numbers in BCD; each digit goes straight to a display with no division. COBOL’s “packed decimal” type, used in banking, is BCD too: decimal fractions like 0.1 are stored exactly and the rounding surprises of Chapter 6 never happen.

The “+6 correction” in BCD additionIf you add two BCD digits in binary, a result above 9 lands on a forbidden pattern: 5 + 8 = 1101 (13, but invalid in BCD). The fix is to add 6: 1101 + 0110 = 1 0011 → carry 1, digit 3, i.e. 13. Why 6? Because the number of unused patterns in a 4-bit box is 16 − 10 = 6. Old Intel processors had a dedicated instruction for this: DAA (decimal adjust after addition).

§ 9.2Gray code: one bit per step

In plain binary counting some steps change several bits at once: going from 7 to 8, 0111 → 1000, all four bits change. If a sensor reading the bits cannot see them all change at exactly the same instant, it can read completely wrong values such as 15 or 0 during the transition. In the reflected binary code Frank Gray applied to patent in 1947, any two consecutive numbers differ in a single bit.

The conversion formula is one line of bit operations: gray = n ^ (n >> 1). Gray code is used today in rotary encoders (disks that read the angle of a motor or a volume knob), in Karnaugh maps, and in hardware circuits that pass counters between clock domains. The word “reflected” comes from the second half of the list being a mirror image of the first.

§ 9.3Parity and Hamming: finding and fixing errors

In Chapter 1 we saw that noise can corrupt bits. Even cosmic rays can flip a bit in memory. The simplest way to detect an error is to add a parity bit: one extra bit that makes the number of 1s even. The receiver counts the 1s; if the count is odd, a bit was corrupted. But which one? Parity cannot say, and if two bits flip it does not notice at all.

In 1950 Richard Hamming found something cleverer: he added 3 parity bits to 4 data bits and placed them so that each parity looks at a different subset of the bits. The ECC memory in servers uses exactly this idea: every 64-bit word gets 8 check bits and single-bit errors are silently corrected on read. QR codes, CDs, DVDs and space probes use a stronger family, Reed–Solomon codes; that is why a scratched CD still plays and a QR code with a torn corner still scans.

§ 9.4Checksums and CRC

Sometimes fixing is unnecessary; noticing that something broke is enough, and then it is requested again. For that a small number summarizing the data is attached. The simplest is adding up all the bytes (mod 256). Internet packets (IP, TCP, UDP) use a 16-bit one’s complement sum (Chapter 5). Ethernet, ZIP and PNG use CRC-32: it treats the data as a giant binary number, divides it by a fixed polynomial (a binary divisor) and keeps the remainder. A sum does not notice two bytes swapping places; a CRC does.

Check digits in your pocketThe last digit of a credit card number is a check digit computed with the Luhn algorithm; mistype a digit and the website notices before sending anything. ISBN book numbers, IBANs and many national ID numbers use the same idea.

§ 9.5Varints: small space for small numbers

Always storing a number in 4 or 8 bytes is wasteful when most numbers are small. A variable-length integer (varint, or LEB128) splits the number into 7-bit pieces and puts each piece in a byte. The leftmost bit of every byte is a continuation flag: 1 means “more bytes follow”, 0 means “I am the last byte”. Numbers from 0 to 127 then take a single byte. Very much like the idea in UTF-8, isn’t it? Google’s Protocol Buffers, WebAssembly and MIDI files use varints.

§ 9.6Base64: turning bytes into text

Some channels, such as e-mail and URLs, carry only safe text characters; the raw bytes of an image cannot pass through. Base64’s solution: line the bytes up and cut them into 6-bit groups. There are 26 = 64 patterns; give each a character: A–Z, a–z, 0–9, + and /. 3 bytes (24 bits) turn into exactly 4 characters. If the end comes up short it is padded with =.

You use Base64 every day: e-mail attachments, small images embedded in web pages (data:image/png;base64,…), files carried inside JSON, and login tokens (JWT) are written in Base64. Beware: Base64 is not encryption; anyone can turn it back.

§ 9.7Before and beside ASCII: Baudot, EBCDIC, Morse

ASCII was not the only character code. The code designed in the 1870s for Émile Baudot’s telegraph, standardized in the 1930s as ITA2, used only 5 bits: 32 patterns. To fit letters and digits it had two special “shift” characters (LTRS and FIGS); the same pattern was a letter or a digit depending on the last shift. It is the ancestor of the Shift key. EBCDIC, which IBM introduced for its mainframes in 1964, was 8 bits and had a strange layout inherited from punched cards: even the letters were not contiguous. It still lives in banks’ mainframes.

§ 9.8Small floats: float16, bfloat16, FP8

In Chapter 6 we saw 32- and 64-bit floats. Graphics cards and AI work with billions of numbers; saving a few bytes per number multiplies memory and speed. So smaller formats were born:

§ 9.916-bit color: RGB565

In Chapter 8 we saw that a color is 24 bits. Old phones, game consoles and the small microcontroller displays of today use 16 bits per color: 5 bits red, 6 bits green, 5 bits blue. Why an extra bit for green? Because the eye is most sensitive to fine differences in green.

§ 9.11Try it yourself

What is decimal 47 in BCD?

  • 0010 1111
  • 0100 0111
  • 0101 0111
  • 0100 1111
4 = 0100, 7 = 0111, side by side. (00101111 is 47 in binary.)

What is the key property of Gray code?

  • It uses fewer bits
  • It represents negative numbers
  • It corrects errors
  • Consecutive numbers differ in a single bit
That is why mechanical sensors do not read wrong values during a transition.

A system using even parity receives 1011 0011. The verdict?

  • There is an error
  • No error
  • The bad bit is bit 3
  • Exactly two bits are bad
There are five 1s: odd, but it should be even. Parity notices the error but cannot say which bit it is in.

How many characters is 10 bytes of data in Base64?

  • 10
  • 14
  • 16
  • 20
⌈10/3⌉ = 4 groups × 4 characters = 16 (the last group has == padding).

Why is bfloat16 popular in AI?

  • It is more precise than float16
  • It offers float32’s range at half the size
  • It is an integer
  • It corrects errors
It keeps float32’s 8-bit exponent field; half the memory without overflow risk.
