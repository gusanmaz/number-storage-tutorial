Text: ASCII & UTF-8

A computer doesn’t know the letter “A”; it only knows numbers. Storing text means agreeing on a letter ↔ number table. In this chapter you will learn those tables — and why accented letters sometimes turn into “Ã©”.

Letters are really numbers

When you press A, the computer writes the number 65 (binary 01000001) into memory. When drawing it on screen, it looks up “what does character number 65 look like?” in a table. The table that maps numbers to characters is called a character encoding. If the writer and the reader use different tables, gibberish appears.

ASCII: the first common 7-bit language

Standardised in 1963, ASCII (American Standard Code for Information Interchange) uses 7 bits to define 128 characters: the English alphabet, digits, punctuation and 33 invisible “control characters”. Since a byte has 8 bits, every ASCII character fits comfortably in one byte.

Hidden cleverness in the table

Digits: '0' = 0x30

Digit characters run from 0x30 to 0x39. The last hex digit is the digit itself! So '7' − '0' = 55 − 48 = 7. That’s how programmers turn a character into a number.

Upper/lower case: one bit apart

'A' = 01000001, 'a' = 01100001. The difference is 32, i.e. just bit 5. Changing case means flipping a single bit.

The line-ending wars

Windows ends lines with two bytes (0D 0A), Linux and macOS with one (0A). That is why lines may merge or show ^M when you open a file on another system. Git’s core.autocrlf setting manages this difference.

print("Line 1\nLine 2")             # \n new line
print("Name:\tAda")                 # \t tab
print("\x48\x65\x6C\x6C\x6F")       # Hello  (hex escape: \xNN)
print("éü")               # éü     (Unicode escape: \uNNNN)
print(ord("A"), chr(97))            # 65 a   (character ↔ code)

ASCII is not enough: Unicode

128 characters have no room for é, ü, ñ, ç or ş, and none at all for Greek, Arabic, Chinese or emoji. In the 1980s every region used the 8th bit to make its own table: ISO-8859-1 (Western Europe), Windows-1252, ISO-8859-9 (Turkish)… But the same byte meant “é” in one table and something else in another; files broke as they travelled.

Unicode ended that chaos by giving every character in the world one permanent number, called a code point, written in hex with U+: U+0041 = A, U+00E9 = é, U+1F600 = 😀. Unicode has room for 1,114,112 code points (U+0000 … U+10FFFF).

Code point ≠ bytes

Unicode only answers “which character has which number”. How that number is written as bytes is a separate decision: UTF-8, UTF-16 and UTF-32 are three different ways.

UTF-8: clever variable-length encoding

UTF-8 writes small code points with few bytes and large ones with more. The leading bits of the first byte tell how many bytes the character uses:

Why is UTF-8 everywhere today?
  • Backwards compatible: pure ASCII text is byte-for-byte identical in UTF-8.
  • Efficient: English text and source code take 1 byte per character.
  • Self-synchronising: bytes starting with 10 are “continuation” bytes; even if you start reading mid-stream you can find character boundaries.
  • Today more than 98% of web pages use UTF-8.

Garbled text (mojibake)

If you’ve seen cafÃ© instead of “café”, the cause is simple: the text was written as UTF-8 but read as Latin-1 / Windows-1252. UTF-8’s 2-byte “é” is drawn as two separate characters from the old table. The Japanese name for this is mojibake (文字化け, “character transformation”).

Read it with the wrong table

A case-conversion trap: the Turkish i

In most languages the uppercase of “i” is “I”, but in Turkish it is “İ” (and the lowercase of “I” is the dotless “ı”). Programming languages apply English rules by default: in JavaScript "i".toUpperCase() → "I", while "i".toLocaleUpperCase("tr") → "İ". Case-insensitive comparisons can therefore behave differently depending on the user’s locale.

Strings in memory

When storing text in memory we also need to know where it ends. Two common approaches:

C: null terminator

48'H'69'i'00\0

The string ends with a byte whose value is 0. strlen("Hi") = 2, but it takes 3 bytes. Forget the trailing 0 and the program keeps reading memory: the classic source of security holes.

Python, JS, Java: length is stored

02length48'H'69'i'

The length is kept alongside the text. Asking for the length is instant, and a string may even contain \0.

Characters ≠ bytes ≠ JS .length

JavaScript strings use UTF-16 internally, and .length counts 16-bit units. Characters above U+FFFF take two units:

"é".length                              // 1
"😀".length                             // 2  (!) two UTF-16 units
[..."😀"].length                         // 1  real character count
new TextEncoder().encode("é").length     // 2  UTF-8 bytes
"é".codePointAt(0).toString(16)          // "e9" → U+00E9

len("é")                     # 1  character
len("é".encode("utf-8"))     # 2  bytes
"é".encode("utf-8")          # b'\xc3\xa9'
hex(ord("é"))                # '0xe9'  → U+00E9
b'\xc3\xa9'.decode("cp1252") # 'Ã©'  ← mojibake!

Summary

  • Text = a sequence of numbers + an encoding that maps them to characters.
  • ASCII is 7 bits (128 characters). Digits start at 0x30, uppercase at 0x41, lowercase at 0x61; the case difference is 32 (one bit).
  • Unicode gives every character a code point (U+XXXX); UTF-8 writes it in 1–4 bytes and is ASCII-compatible.
  • Mojibake comes from writing and reading with different encodings.
  • C strings end with \0; higher-level languages store the length separately.
