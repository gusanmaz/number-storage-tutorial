§ 11.1Writing numbers in code

There is no difference at all between writing 255, 0xFF, 0o377 and 0b11111111 in code: all four become the same bit pattern in memory. They are called number literals. The prefix only tells the compiler which base to read the digits in. The base is not stored in the variable.

An old trapIn C and old JavaScript a number starting with 0 is read as octal: 010 is not ten but eight. Python 3 banned this completely (SyntaxError), and JavaScript’s strict mode does not allow it. If you want octal, always write 0o.

§ 11.2Languages store integers differently

In Chapter 3 we saw that fixed-width boxes can overflow, and in Chapter 6 that doubles skip integers after 253. Languages deal with these limits in different ways:

  • C, Java, Go: int8, int32, uint64… Fixed width; they wrap around on overflow.
  • Python: int is unbounded. As the number grows Python gives it more bytes; 2**1000 is no problem. The price: some slowness.
  • JavaScript: every number is a double. Integers are safe up to 253 − 1 (Number.MAX_SAFE_INTEGER). For bigger ones there is BigInt, written with a trailing n: 2n ** 100n. And a surprise: bitwise operators temporarily convert the number to a signed 32-bit integer.

§ 11.3Bitwise operations

Bitwise operations treat two numbers not as numbers but as columns of bits, and apply the logic gates of Chapter 1 in every column. The processor does them in a single step, which is why they are everywhere in low-level code, graphics, cryptography and compression.

Why is ~5 equal to −6 in Python?

Think first, then open

~ flips every bit. In two’s complement “flip every bit” means −x − 1 (the first half of Chapter 5’s “flip, add 1” rule). So ~5 = −5 − 1 = −6.

§ 11.4Masks and flags

We can use a byte as 8 separate yes/no switches. We give each bit a meaning (these are called flags) and read or change them one by one with bitwise operations. The best-known example is Unix file permissions: read (r), write (w) and execute (x) for the owner, the group and everyone else. 9 bits; grouped in threes, so written in octal. The 755 in chmod 755 is exactly this.

Four basic patterns are worth memorizing:

READ, WRITE, EXEC = 0b100, 0b010, 0b001   # 4, 2, 1

perm = READ | WRITE            # add a flag (OR)          → 0b110
if perm & WRITE:               # test a flag (AND)
    print("writable")
perm &= ~WRITE                 # remove a flag (AND NOT)  → 0b100
perm ^= EXEC                   # toggle a flag (XOR)      → 0b101

color = 0xFF8800
green = (color >> 8) & 0xFF    # extract a field: shift + mask → 136

const READ = 0b100, WRITE = 0b010, EXEC = 0b001;

let perm = READ | WRITE;        // add
if (perm & WRITE) console.log("writable");
perm &= ~WRITE;                 // remove
perm ^= EXEC;                   // toggle

const isOdd = (n) => (n & 1) === 1;      // last bit 1 means odd
const isPowerOfTwo = (n) => n > 0 && (n & (n - 1)) === 0;

§ 11.5Is a variable a box or a label?

In Chapter 10 we said a variable name is a nickname for an address. In C that is exactly right: int a is a box and b = a copies the bytes inside the box. In Python and JavaScript the story is a bit different, and it is the source of many bugs.

In Python every value is an object that lives at its own place in memory. A variable is a label stuck on that object. b = a does not create a new object; it sticks a second label on the same object. In JavaScript, primitive values such as numbers, strings and booleans are copied directly, while arrays and objects are shared by reference, as in Python.

Immutable: in Python int, float, str, tuple; in JavaScript all primitive types. Sharing them is safe; “changing” always produces a new value.

Mutable: list, dict, set, and arrays and objects in JavaScript. Changing a shared object in place affects every name that points to it.

Identity and equality are different questions. == asks “is the content the same?”, Python’s is asks “is it the same object?”. In CPython id(x) is the object’s address in memory; this is exactly where Chapter 10 connects.

a = [1, 2, 3]
b = a              # the same object
c = a[:]           # new object, same content (shallow copy)
print(a == c, a is c)     # True False
print(a is b)             # True
print(hex(id(a)))         # like '0x7f3a2c1d4e80': an address!

def add(lst):
    lst.append(99)        # changes the caller’s list!
add(a); print(b)          # [1, 2, 3, 99]

import copy
m = [[0, 0], [0, 0]]
s = m.copy()              # shallow: inner lists are shared
d = copy.deepcopy(m)      # deep: everything is new
m[0][0] = 7
print(s[0][0], d[0][0])   # 7 0

const a = [1, 2, 3];
const b = a;               // the same array
const c = [...a];          // new array (shallow copy)
console.log(a === c, a === b);  // false true

a.push(4);                 // const, yet it can change!
// a = [];                 // TypeError: assignment to const

let x = 10, y = x;         // primitive: the value is copied
y++;
console.log(x, y);         // 10 11

const m = [[0, 0], [0, 0]];
const s = [...m];                    // shallow
const d = structuredClone(m);        // deep
m[0][0] = 7;
console.log(s[0][0], d[0][0]);       // 7 0

const (JavaScript) forbids moving the name to another object, not changing the object’s insides. When you pass a list to a function or assign it to another variable you share the list itself, not a copy. If you want a copy, make it explicitly.

The secret of small numbersCPython creates the integers from −5 to 256 in advance and reuses them. So a = 256; b = 256; a is b can be true while the same thing for 257 can be false. The lesson: compare numbers and strings with ==, not is. Use is only for None.

Why is (1 << 31) negative in JavaScript?

  • A bug
  • Because there is no overflow
  • Bitwise operators work on signed 32-bit integers; bit 31 is the sign bit
  • JavaScript likes negative numbers
The result is −2,147,483,648. For unsigned, use (1 << 31) >>> 0.
