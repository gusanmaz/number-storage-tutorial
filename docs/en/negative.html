Chapter 5

Negative numbers on a clock face

Lamps have no “minus” state. Yet a computer has to store −5. History tried four different solutions; one of them turned out so elegant that it even makes subtraction disappear. We will tinker with all four and compare them.

Reading: ~50 minBefore: Chapters 2–4

§ 5.1The first idea: reserve a bit for the sign

The most natural idea is to use the leftmost bit as the sign: 0 for plus, 1 for minus, and the remaining seven bits for the size of the number. This is called sign-magnitude: +5 = 00000101, −5 = 10000101. It looks reasonable on paper but has two problems.

First, there are two zeros: 00000000 (+0) and 10000000 (−0). Two patterns for one value means checking two cases in every comparison. Second, and worse: ordinary addition breaks. Add +3 and −3 with normal binary addition and you get 00000011 + 10000011 = 10000110, which is −6. The processor would need separate circuits that know separate rules for negative numbers.

Even comparing numbers is awkward in this design: read as unsigned, −1 (10000001) looks smaller than −5 (10000101). Early machines such as the IBM 7090 used sign-magnitude. The idea is not entirely dead: the sign bit of the floating-point numbers in Chapter 6 works exactly like this.

§ 5.2Second attempt: one’s complement

Another idea: get the negative of a number by flipping all its bits. +5 = 00000101, −5 = 11111010. This is called one’s complement; the name comes from subtracting every bit from 1: x plus flip(x) is always 11111111. The leftmost bit still shows the sign, and 8 bits hold −127 … +127.

Addition almost works in this representation. It needs one extra rule: if a carry leaves the leftmost column, instead of dropping it you add it back at the right end of the result. This is called the end-around carry. Try it: + .

One’s complement was used in the 1960s on supercomputers like the CDC 6600 and on UNIVAC machines. But it had two flaws: there are still two zeros (00000000 and 11111111), and the end-around carry sometimes means doing the addition twice. Yet the idea lives on inside the internet every moment: the checksum in IP, TCP and UDP packets is computed with one’s complement addition, because it is independent of byte order and the end-around carry never loses a bit (Chapter 9).

Is there a way with a single zero and no extra rules? To find it, let’s get in a car.

§ 5.3The odometer that rolls back

Picture a three-digit odometer in an old car. Drive backwards and it counts down: 002, 001, 000… and then? 999. Try it below.

This observation changes everything: on a fixed-width counter, we can call the patterns that go backwards from zero negative numbers. 999 = −1, 998 = −2, 997 = −3… And ordinary addition works with them: 5 + 999 = 1004 → last three digits 004 = 5 − 1. Drop the overflowing digit and the result is right!

§ 5.4The same idea in binary: the number wheel

Let’s arrange the 4-bit numbers on a clock face. After 1111 comes 0000; the wheel wraps around. Step back once from 0000 and you land on 1111. So calling 1111 −1 is very natural. Drag the hand or use the buttons, and change the interpretation.

On the wheel, subtracting 3 means going 3 steps counterclockwise. That lands in the same spot as going 13 steps clockwise (16 − 3 = 13). So instead of computing 7 − 3 the processor can compute 7 + (−3); no separate subtraction circuit is needed. This system is called two’s complement and almost every processor today uses it.

§ 5.5The hidden value of the leftmost bit

The wheel has a shortcut: in two’s complement the leftmost bit is worth −128, not +128 (in 8 bits). The other bits stay the same. So when the leftmost bit is on, the number automatically drops below zero. Compare the two readings of the same eight bits.

§ 5.6Negating a number: flip and add 1

For hand calculation there is a handy rule: to negate a number, flip all the bits and add 1. Why does it work? A number plus its flipped version has one 0 and one 1 in every column: the sum is 11111111, which is −1. So x + flip(x) = −1, hence flip(x) + 1 = −x.

The rule works both ways: negate −5 and you are back at +5. There is one exception: the negative of −128 cannot be written in 8 bits, because +128 is out of range. The signed range is asymmetric: with n bits, −2n−1 … 2n−1 − 1. Zero takes one slot from the positive side.

WidthUnsignedSigned (two’s complement)
8 bit0 … 255−128 … 127
16 bit0 … 65,535−32,768 … 32,767

Where does the name come from? One’s complement subtracts every bit from 1, i.e. subtracts the number from 11111111 = 2n − 1. Two’s complement subtracts it from 2n, one more: −x = 2n − x. In 8 bits −5 = 256 − 5 = 251 = 11111011. So “flip, add 1” and “subtract from 256” are the same thing. Another quick way: keep the bits from the right up to and including the first 1, and flip everything to its left.

§ 5.7The fourth way: excess (biased) representation

There is a completely different idea too: add a fixed K to every number and store the result as unsigned. The value of a pattern = unsigned value − K. With 8 bits and K = 128, 00000000 = −128, 10000000 = 0, 11111111 = +127. This is called excess-K (offset binary, or biased) representation.

§ 5.9Sign extension

When you move an 8-bit number into a 16- or 32-bit box, what do you fill the empty upper bits with? For unsigned numbers the answer is easy: zeros (zero extension). But in two’s complement, putting zeros in front of −5 = 11111011 gives 00000000 11111011 = 251. The right way is to copy the sign bit: 11111111 11111011 = −5.

Processors have separate instructions for this (MOVSX and MOVZX on x86). The compiler picks one based on the type; if the type is wrong, the bug is sneaky. A classic example: a 0xFF byte read from a file becomes −1 in Java because byte is signed, and turns into 0xFFFFFFFF when converted to int. In C, whether plain char is signed or unsigned even depends on the platform.

signed char   s = (signed char)0xFF;   // -1
unsigned char u = 0xFF;                // 255
int a = s;      // -1          (sign-extended: 0xFFFFFFFF)
int b = u;      // 255         (zero-extended: 0x000000FF)

const b = new Int8Array([0xFF])[0];    // -1  (signed byte)
console.log(b, b & 0xFF);             // -1 255
// sign-extending an 8-bit value by hand:
const sx8 = (x) => (x << 24) >> 24;   // 0xFB → -5
console.log(sx8(0xFB));

x = 0xFB
print(x - 256 if x & 0x80 else x)      # -5   manual sign extension
print(int.from_bytes(b"\xfb", "big", signed=True))   # -5
print(int.from_bytes(b"\xfb", "big"))                # 251

§ 5.10Shifting negative numbers

In Chapter 4 we saw that a right shift divides by 2. But shift −12 = 11110100 right while feeding a 0 in from the left and you get 01111010 = 122. Signed numbers use an arithmetic right shift: the sign bit is copied into the vacated place on the left. So −12 >> 1 = −6. A shift that always feeds in 0 is called a logical shift.

§ 5.11The silent disaster: overflow

Two’s complement has a price. Because the wheel wraps around, an operation whose result does not fit in the box raises no error; it quietly produces a wrong number. The rule for signed overflow is simple: if two numbers of the same sign add up to a result of the opposite sign, it overflowed. Two numbers of different signs never overflow. § 5.12Overflow in real life

Overflow has caused some of the most expensive bugs in software history:

  • Pac-Man (1980): The level counter was 8 bits. At level 256 the counter overflowed, the right half of the screen filled with garbage and the game became unplayable.
  • Ariane 5 (1996): A 64-bit floating-point velocity value did not fit when converted to a 16-bit signed integer. The rocket destroyed itself about 40 seconds after launch.
  • Nuclear Gandhi (a legend): The story goes that in Civilization the most peaceful leader’s aggression score of 1, reduced by 2, wrapped around to 255 in an unsigned byte and made him the most aggressive leader. The game’s designer said it never actually happened; the story spread because it shows how counterintuitive unsigned wraparound is.
  • Gangnam Style (2014): YouTube’s view counter was a signed 32-bit integer: at most 2,147,483,647. As the video approached that limit, the counter was upgraded to 64 bits.

§ 5.13Negative numbers and overflow in code

One more trap: the absolute value of the smallest number cannot be written. In 32 bits abs(-2147483648) is undefined in C and in practice returns −2,147,483,648 again. In Java Math.abs(Integer.MIN_VALUE) returns a negative number. Python’s unbounded integers never hit this; but the fact that ~x is −x − 1 in Python shows that it imagines an infinitely wide two’s complement behind the scenes.

# Python integers grow without limit and never overflow:
print(2 ** 100)                        # 1267650600228229401496703205376

# Imitate C types and you can see overflow:
import ctypes
print(ctypes.c_int8(127 + 1).value)    # -128
print(ctypes.c_uint8(255 + 1).value)   # 0

// JS numbers are 64-bit floats; an 8-bit overflow with a typed array:
const a = new Int8Array([127]);
a[0] += 1;
console.log(a[0]);          // -128

// Bitwise operators convert to signed 32-bit:
console.log(2147483647 | 0);       // 2147483647
console.log((2147483647 + 1) | 0); // -2147483648

#include <stdint.h>
uint8_t u = 255;  u = u + 1;   // 0   (unsigned wraparound is well defined)
int     x = 2147483647;
x = x + 1;                     // UNDEFINED BEHAVIOR: signed overflow

§ 5.14Try it yourself

In 8-bit two’s complement, what is 11111111?

  • 255
  • −1
  • −127
  • −128
−128 + 127 = −1. One step back from 0 on the wheel.

Which is −6 in 8-bit two’s complement?

  • 10000110
  • 11111001
  • 00000110
  • 11111010
6 = 00000110 → flip: 11111001 → +1: 11111010. (10000110 is sign-magnitude.)

What is 127 + 1 in an 8-bit signed variable?

  • −128
  • 128
  • 0
  • The program stops
01111111 + 1 = 10000000 = −128. We crossed the red line on the wheel.

The main reason processors prefer two’s complement?

  • It fits more positive numbers
  • It is easy to read
  • The adder circuit can subtract too
  • It uses fewer bits
a − b = a + (−b). One adder is enough and there is only one zero.

How is −5 written in 8-bit one’s complement?

  • 11111011
  • 11111010
  • 10000101
  • 00000101
Just flip the bits: 00000101 → 11111010. (11111011 is two’s complement.)

Which representation does not have two zeros?

  • Sign-magnitude
  • One’s complement
  • All of them do
  • Two’s complement
In two’s complement −0 = flip(0) + 1 = 00000000 = 0. Excess-K also has a single zero.

The 8-bit signed 0x9C sign-extended to 16 bits?

  • 0xFF9C
  • 0x009C
  • 0x9C00
  • 0x8000
0x9C = 1001 1100; the top bit is 1 → high byte FF. The value is −100.

Two negative numbers added up to a positive result. Which flag is certainly 1?

  • Z
  • N
  • V
  • None
If two numbers of the same sign give a result of the opposite sign, there was a signed overflow: V = 1.

Which representation does the exponent field of an IEEE 754 float use?

  • Two’s complement
  • Excess-127
  • One’s complement
  • Sign-magnitude
The exponent + 127 is stored, so floats can be compared like integers.
