Chapter 4

Negative numbers on a clock face

Lamps have no “minus” state. Yet a computer has to store −5. The solution people found is so elegant that it even makes subtraction disappear.

Reading: ~25 minBefore: Chapters 2–3

§ 4.1The first idea: reserve a bit for the sign

The most natural idea is to use the leftmost bit as the sign: 0 for plus, 1 for minus, and the remaining seven bits for the size of the number. This is called sign-magnitude: +5 = 00000101, −5 = 10000101. It looks reasonable on paper but has two problems.

First, there are two zeros: 00000000 (+0) and 10000000 (−0). Two patterns for one value means checking two cases in every comparison. Second, and worse: ordinary addition breaks. Add +3 and −3 with normal binary addition and you get 00000011 + 10000011 = 10000110, which is −6. The processor would need separate circuits that know separate rules for negative numbers.

For a better idea, let’s get in a car.

§ 4.2The odometer that rolls back

Picture a three-digit odometer in an old car. Drive backwards and it counts down: 002, 001, 000… and then? 999. Try it below.

This observation changes everything: on a fixed-width counter, we can call the patterns that go backwards from zero negative numbers. 999 = −1, 998 = −2, 997 = −3… And ordinary addition works with them: 5 + 999 = 1004 → last three digits 004 = 5 − 1. Drop the overflowing digit and the result is right!

§ 4.3The same idea in binary: the number wheel

Let’s arrange the 4-bit numbers on a clock face. After 1111 comes 0000; the wheel wraps around. Step back once from 0000 and you land on 1111. So calling 1111 −1 is very natural. Drag the hand or use the buttons, and change the interpretation.

On the wheel, subtracting 3 means going 3 steps counterclockwise. That lands in the same spot as going 13 steps clockwise (16 − 3 = 13). So instead of computing 7 − 3 the processor can compute 7 + (−3); no separate subtraction circuit is needed. This system is called two’s complement and almost every processor today uses it.

§ 4.4The hidden value of the leftmost bit

The wheel has a shortcut: in two’s complement the leftmost bit is worth −128, not +128 (in 8 bits). The other bits stay the same. So when the leftmost bit is on, the number automatically drops below zero. Compare the two readings of the same eight bits.

§ 4.5Negating a number: flip and add 1

For hand calculation there is a handy rule: to negate a number, flip all the bits and add 1. Why does it work? A number plus its flipped version has one 0 and one 1 in every column: the sum is 11111111, which is −1. So x + flip(x) = −1, hence flip(x) + 1 = −x.

The rule works both ways: negate −5 and you are back at +5. There is one exception: the negative of −128 cannot be written in 8 bits, because +128 is out of range. The signed range is asymmetric: with n bits, −2n−1 … 2n−1 − 1. Zero takes one slot from the positive side.

§ 4.6The silent disaster: overflow

Two’s complement has a price. Because the wheel wraps around, an operation whose result does not fit in the box raises no error; it quietly produces a wrong number. Compute 100 + 50 in an 8-bit signed variable:

Overflow has caused some of the most expensive bugs in software history:

  • Pac-Man (1980): The level counter was 8 bits. At level 256 the counter overflowed, the right half of the screen filled with garbage and the game became unplayable.
  • Ariane 5 (1996): A 64-bit floating-point velocity value did not fit when converted to a 16-bit signed integer. The rocket destroyed itself about 40 seconds after launch.
  • Gangnam Style (2014): YouTube’s view counter was a signed 32-bit integer: at most 2,147,483,647. As the video approached that limit, the counter was upgraded to 64 bits.

One overflow is approaching right now. Many systems store time as “seconds since 1 January 1970” in a signed 32-bit integer. Here is that number at this moment:

Overflow in code

# Python integers grow without limit and never overflow:
print(2 ** 100)                        # 1267650600228229401496703205376

# Imitate C types and you can see overflow:
import ctypes
print(ctypes.c_int8(127 + 1).value)    # -128
print(ctypes.c_uint8(255 + 1).value)   # 0

// JS numbers are 64-bit floats; an 8-bit overflow with a typed array:
const a = new Int8Array([127]);
a[0] += 1;
console.log(a[0]);          // -128

// Bitwise operators convert to signed 32-bit:
console.log(2147483647 | 0);       // 2147483647
console.log((2147483647 + 1) | 0); // -2147483648

#include <stdint.h>
uint8_t u = 255;  u = u + 1;   // 0   (unsigned wraparound is well defined)
int     x = 2147483647;
x = x + 1;                     // UNDEFINED BEHAVIOR: signed overflow

§ 4.7Try it yourself

In 8-bit two’s complement, what is 11111111?

  • 255
  • −1
  • −127
  • −128
−128 + 127 = −1. One step back from 0 on the wheel.

Which is −6 in 8-bit two’s complement?

  • 10000110
  • 11111001
  • 00000110
  • 11111010
6 = 00000110 → flip: 11111001 → +1: 11111010. (10000110 is sign-magnitude.)

What is 127 + 1 in an 8-bit signed variable?

  • −128
  • 128
  • 0
  • The program stops
01111111 + 1 = 10000000 = −128. We crossed the red line on the wheel.

The main reason processors prefer two’s complement?

  • It fits more positive numbers
  • It is easy to read
  • The adder circuit can subtract too
  • It uses fewer bits
a − b = a + (−b). One adder is enough and there is only one zero.
