Files: everything is bytes

A photo, a song, a Word document or a program… On disk they are all the same thing: a long sequence of bytes. In this chapter you will look inside files with a hex viewer and see everything from the previous chapters come together.

⏱ ~30 minPrerequisites: Text, Colors, Sound, Memory
By the end of this chapter you will
  • be able to explain that a file’s contents and its name/extension are different things;
  • read a hex dump;
  • recognise a file type from its first bytes (its signature);
  • decode integers, text and byte order in a file header;
  • understand the basic idea of compression (shortening repetition).

File = name + byte sequence

The operating system keeps a few facts about a file: its name, size, dates and permissions. The file’s contents, however, are just bytes; there is no magic label inside saying “I am a photo”. What the bytes mean is decided by the format known to the program reading them. A text editor reads the same bytes as letters, an image viewer as pixels, a music player as audio samples.

An extension is just a name

Renaming photo.jpg to photo.txt doesn’t change a single byte inside; the operating system just opens it with the wrong program. That’s why programs that need to know a file’s type reliably look not at the extension but at the file’s first bytes.

Hex viewer

Programmers look at a file’s raw contents with a hex dump: the position (offset) on the left, the hex values of 16 bytes per row in the middle, and the ASCII form of the same bytes on the right (unprintable ones shown as .). Pick a sample file or open one from your computer.

What to look for in the viewer
  • In BMP and WAV headers integers are written little-endian (formats with Windows/Intel roots). PNG uses big-endian.
  • Most formats carry readable ASCII letters in their first bytes: BM, RIFF, WAVE, PNG, %PDF.
  • The pixel data at the end of the BMP follows the same logic as the pixel editor’s byte sequence in the Colors chapter (but rows go bottom to top, in BGR order!).

What do you see if you rename a .docx file to .zip and open it?

Show answer

A folder structure! Inside are files such as word/document.xml where the text lives and word/media/ for images. DOCX is XML files packed with ZIP. The signature (PK) gives it away.

Text files and binary files

Text file (.txt, .py, .html, .csv)

All bytes are letters, digits, spaces and line endings in some character encoding (usually UTF-8). Any editor can read it. In the hex viewer, the ASCII column shows meaningful text.

Binary file (.png, .mp3, .exe)

The bytes are integers, floats, pixels and audio samples. Open one in a text editor and you’ll see gibberish, because the editor forces these bytes to be read as characters.

Compression: the same information in fewer bytes

In the Colors and Sound chapters you saw how big raw data is. The basic idea of compression is to spot repetition in the data and shorten it. The simplest method is RLE (Run-Length Encoding): write runs of repeated values as “count + value”.

Compress with RLE

Real compressors

ZIP, PNG and gzip use smarter methods: they write repeated byte sequences as back-references to earlier data (LZ77) and give frequent values short bit codes and rare ones longer codes (Huffman coding). JPEG and MP3 first throw away information the eye/ear won’t notice. But no compressor can shrink truly random data: with no repetition, there’s nothing to shorten.

Summary

  • A file’s contents are just bytes; the format gives them meaning, the extension is only a hint.
  • Hex dump: offset + 16 bytes of hex + ASCII. The universal way to inspect files.
  • File types are recognised by signatures in the first bytes (PNG: 89 50 4E 47, PDF: %PDF, ZIP: PK).
  • File headers use everything from earlier chapters: ASCII tags, little/big-endian integers, pixel and audio data.
  • Compression shortens repetition; random data cannot be compressed.

  • 800
  • 537,067,520

  • 2003
Little-endian: 0x00000320 = 3 × 256 + 32 = 800.

  • W6B3
  • 6W3B
  • 6W4B1W
  • 6W3B1W
6 W, 3 B, 1 W.

What happens if you rename a .jpg file to .png?

  • The file is converted to PNG
  • The contents don’t change; it is still JPEG data
  • The file gets smaller
  • The file is corrupted and never opens again
Renaming doesn’t touch the bytes. Most viewers check the signature and open it anyway.
